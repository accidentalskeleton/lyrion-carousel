# Spotify / Spotty experiment

Branch: `experiment/spotify-spotty`

## Architecture

This experiment deliberately keeps the audio path under LMS control:

```text
Lyrion Carousel -> LMS JSON-RPC -> Spotty -> Spotify
                         |
                         +-> Squeezelite -> Digi2 Pro -> DSP -> DAC
```

Carousel does not store Spotify credentials and does not use Spotify Web Playback. Spotty remains responsible for Spotify authentication and streaming.

## Implementation

`js/spotify.js` is a provider boundary which:

- discovers Spotty through LMS BrowseLibrary;
- follows the actions returned by LMS instead of calling Spotify endpoints directly;
- normalizes Spotty album menu entries into source-neutral album records;
- can load a Spotify album on the selected LMS player with `playlist play spotify:album:...`;
- exposes a diagnostic `probeSpotty()` so the real server response can be captured before the provider is wired into the production carousel.

The current Spotty source builds its personal Albums entry in `OPML.pm` and returns album menu items carrying Spotify URIs. This provider intentionally consumes the LMS menu representation rather than Spotty's private Perl API.

## Live validation required

The first live test must be run against the actual `mrlazy` LMS/Spotty installation because BrowseLibrary action payloads are generated by LMS and can vary with LMS/Spotty versions, account state and menu registration.

In the browser developer console on this branch:

```js
const { probeSpotty } = await import('./js/spotify.js');
probeSpotty('<PLAYER-ID>').then(console.log);
```

Use the MAC-style LMS player id shown by Carousel Settings. A successful probe should return `available: true` and include the Spotty root items, normally including Albums, Artists and Playlists.

Do not merge the source selector into the main UI until this probe is confirmed on the real server. That prevents a guessed BrowseLibrary payload from destabilising the existing 0.9.0 catalogue.

## Next integration after probe

Once the returned action structure is verified:

1. add Library / Spotify source selection;
2. use `savedSpotifyAlbums()` for the Spotify album shelf/fan;
3. proxy/cache remote Spotify artwork through the Carousel server rather than hot-linking it;
4. adapt search so local LMS and Spotty results can be shown separately;
5. keep queue, transport and CometD player status shared because playback still belongs to LMS;
6. add Spotify playlists and artists as secondary browse screens.

The application VERSION remains unchanged on this experimental branch.
